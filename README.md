# إنجازي — Injazi

تطبيق Flutter لأندرويد لمتابعة الإنجازات اليومية: تسجّل ما أنجزته كل يوم، وتحدّد
إنجازاتك وأهدافك بنفسك، مع خطط متكرّرة وتقويم بالساعات وتذكيرات ذكية.

## المزايا

- **إنجازات اليوم**: إضافة سريعة، خطوات فرعية، وسوم، أولويات، فئات قابلة للتخصيص.
- **خطط متكرّرة**: يوميًا / أسبوعيًا (اختيار أيام مثل «كل ثلاثاء») / كل ن يوم /
  شهريًا، مع تاريخ بداية ونهاية اختياري، وإيقاف مؤقت وتخطّي أيام.
  - تُحسب **أيام الدوام** وأيام الراحة في كل خطة حسب أيام الدوام المحددة في الإعدادات.
- **تقويم غني**: عرض شهري وأسبوعي ويومي + خط زمني بالساعات («١٩:٠٠ → ٢٠:٠٠»).
- **تذكير نهاية اليوم (٢١:٠٠ افتراضيًا)**: إشعار يسرد ما لم يُنجز بعد، وقابل
  للتعديل من الإعدادات. مع أزرار «أنجزت ✓» و«تأجيل» تعمل من الإشعار نفسه.
  إضافة إلى تذكير الصباح، والتنبيهات المتكرّرة، والصوت المخصّص والاهتزاز.
- **تقارير وإحصاءات**: نسبة الإنجاز، السلسلة، سجل الأيام، توزيع الفئات،
  أكثر ساعات الإنتاج، وخريطة حرارية للأشهر.
- **شارات ومستويات**: نقاط خبرة ومستويات و١٢ شارة تحفيزية.
- **مؤقّت تركيز**: جلسات تركيز مرتبطة بالخطة/المهمة مع احتساب دقائق التركيز.
- **بحث وملاحظات يومية وخلفية مزاجية**، ونسخ احتياطي (تصدير/استيراد JSON).
- **تصميم أنيق**: عربي RTL أصلي، ٨ ثيمات لونية، وضع فاتح/غامق، كثافة عرض،
  حجم خط، وحواف قابلة للضبط، وخطوط Cairo و Readex Pro.
- **أيقونة هادئة** وصوت إشعار مخصّص (٤ أصوات: هادئة، نقية، جرس، خفيفة).

## البناء

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release      # ينتج build/app/outputs/flutter-apk/app-release.apk
```

> نسخة الإصدار تُوقّع حاليًا بمفتاح التصحيح (debug) لتسهيل التجربة.
> للنشر: أنشئ keystore خاصًا بك وأضف إعدادات التوقيع في
> `android/app/build.gradle.kts`.

## تنزيل ملف APK الجاهز

كل نسخة تُدفع إلى هذا الفرع تُشغّل تلقائيًا: `flutter analyze` ثم `flutter test`.
ويمكن تنزيل ملف APK جاهز للتجربة دون أي إعداد محلي:

1. افتح صفحة **Actions**: `https://github.com/ogooom11-lgtm/gunluk-20-146-166/actions`
2. اختر آخر تشغيل ناجح باسم «بناء APK».
3. من قسم **Artifacts** نزّل `injazi-release-apk` ثم فك الضغط → `app-release.apk`.

لبناء الملف في تشغيل جديد، أضف `[apk]` في رسالة الـ commit (أو شغّل الـ workflow
يدويًا مع تفعيل `build_apk`). في حال فشل التحليل أو الاختبارات أو البناء، ينشر
الـ workflow تقريرًا مختصرًا كتعليق على الـ commit نفسه يوضّح الأخطاء.

## بنية المشروع

```
lib/
  core/        enums، أدوات التواريخ والأوقات (ميلادي/هجري)، النصوص (ar/en)، النماذج
  data/        التخزين المحلي (SharedPreferences)، حالة التطبيق، مُخطِّط التذكيرات
  services/    الإشعارات (قنوات، أصوات، جدولة، أزرار) + المنطقة الزمنية
  theme/       الثيمات واللوحات اللونية والمقاسات
  ui/          الشاشات والأدوات: الرئيسية، التقويم، الخطط، التقارير، الإعدادات…
test/          اختبارات المنطق الخالص (تواريخ، مهام، خطط، إحصاءات، تذكيرات، نصوص،
               واجهات وتقويم/خط زمني/ورق الإضافة السريعة، وسريان السمة واللغة فورًا)
```

واستيرادها في أي وقت من: الإعدادات ← البيانات ← نسخ احتياطي.
